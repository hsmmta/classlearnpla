## 🔍 如果还是有问题

### 问题A：管理员仍然看不到待审核问题

**检查清单**：
1. 在 MySQL 中执行：`SELECT COUNT(*) FROM question WHERE questionState = '待审核';`
   - 如果结果为 0，说明数据库中没有待审核问题
   - 需要用户提交新问题

2. 检查是否真的以管理员身份登录
   - 查看浏览器 Cookie 中是否有 JSESSIONID
   - Session 中 userType 应该是 "admin"

3. 直接访问审核 Servlet（绕过导航栏）：
   - `http://localhost:8080/焚决/discussion/audit`
   - 如果能看到问题列表，说明 Servlet 工作正常，问题在导航栏链接
   - 如果显示"无权限"，说明 session 中没有正确的 userType

### 问题B：用户无法上传资料

**检查错误信息**：
如果看到错误页面，它会显示：
- "错误详情：xxx" → MySQL 错误信息
- "userID: xxx" → 实际的 userID 值

常见错误：
- `Foreign key constraint fails` → userID 不存在于 user 表
  - 解决：用户重新登录，确保 userID 正确

- `Duplicate entry` → 资料 ID 重复（极少见）
  - 解决：重新尝试上传

- 没有看到任何错误信息 → UploadMaterialServlet 没有被编译
  - 解决：重新执行 mvn clean compile mvn package

## ⚠️ 关键点

### 为什么需要删除 work 目录？

Tomcat 在 `work` 目录中缓存已编译的 JSP 文件和类。如果不删除，Tomcat 会继续使用旧的编译文件，新代码不会生效。

### 为什么需要删除 webapps 文件夹？

当 Tomcat 启动时，如果看到 `焚决.war` 文件，会自动解压到 `webapps/焚决`。如果不删除旧文件夹，可能会保留旧的文件。

### 相对路径 vs 绝对路径

- ❌ `<a href="../material/audit">` → 相对路径，可能不正确
- ✅ `<a href="${pageContext.request.contextPath}/material/audit">` → 绝对路径，总是正确
